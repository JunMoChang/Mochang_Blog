# 虚函数

当类中有虚函数时，编译器会在对象**起始处**放一个虚函数指针（`vfptr`，64 位下占 8 字节），数据成员排在它后面；这个指针指向一张虚函数指针数组，也就是虚函数表（`vtbl`）。调用虚函数的时候，会用 `vfptr` 去找到该对象**动态类型**的 `vtbl`，在 `vtbl` 中找到该虚函数的地址然后执行。

子类会照着基类的 `vtbl` 复制一份布局，槽位顺序和基类保持一致：如果子类没有重写基类虚函数，表中对应槽位仍然是基类虚函数地址；如果重写了，对应位置则是子类自己重写的虚函数地址；只有**子类新增的、基类里没有的虚函数**才会加到自己 `vtbl` 的末尾。

**只有基类的析构函数是虚函数时**，子类析构函数才会覆盖基类那对析构槽位；如果基类析构函数不是虚函数，基类的表里根本没有析构槽位——子类写**普通析构**时它不是虚函数、不在表里；子类**显式写 `virtual`** 时才是虚函数、但排在继承槽位之后。

```C++
class Animal {
public:
    virtual ~Animal() = default;
    virtual void eat()
    {
        std::cout << "Animal::eat" << std::endl;
    }
};

class Dog : public Animal {
public:
    virtual ~Dog() = default;
    void eat()
    {
        std::cout << "Dog::eat" << std::endl;
    }
};

class Cat : public Animal {
public:
    virtual ~Cat() = default;
};
```

```c++
int main()
{
    Animal* animal = new Animal();
    animal->eat(); //输出 Animal::eat

    Animal* dog_animal = new Dog();
    dog_animal->eat(); //输出 Dog::eat

    Dog* dog = new Dog();
    dog->eat(); //输出 Dog::eat

    Cat* cat = new Cat();
    cat->eat();// 输出 Animal::eat
    
    std::cout << "---------- delete animal ----------" << std::endl;
    delete animal;
    std::cout << "---------- delete dog_animal ----------" << std::endl;
    delete dog_animal;
    std::cout << "---------- delete dog ----------" << std::endl;
    delete dog;
    std::cout << "---------- delete cat ----------" << std::endl;
    delete cat;
}
```

<img src="vtbl_animal_dogAnimal.png" width="49%" /> <img src="vtbl_dog_cat.png" width="49%" />

`Animal*` 类型的 `dog_animal` 和 `Dog*` 类型的 `dog` 指向的对象都是 `Dog` 类型，图中两者的表地址完全相同，所以**同一个类型的对象共享一张虚函数表**。（`info vtbl dog_animal` 显示的是 `vtable for 'Animal'`，是因为它的**静态类型**是 `Animal*`，但表里的内容其实是 `Dog` 的表。）

另外，每个表的 `[0]`、`[1]` 两项都是析构函数，Itanium ABI 给虚析构函数分配了两个入口——完整对象析构 `~D1()` 和删除对象析构 `~D0()`（`delete p` 时由它负责先调析构、再调 `operator delete`），gdb 把两个都反解成了同一个名字。所以这里 `Animal` 的表其实只有两个虚函数：析构（占 2 个槽位）和 `eat`。

`Cat` 没有重写基类的虚函数，所以 `Cat` 的 `vtbl` 对应位置是基类 `Animal::eat` 的地址；`Dog` 重写了基类的虚函数，所以 `Dog` 的 `vtbl` 对应位置是 `Dog::eat`。

### 虚析构函数

将上述基类的析构函数改成普通析构函数

```C++
class Animal {
public:
    ~Animal()
    {
        std::cout << "Animal::~Animal" << std::endl;
    }

    virtual void eat()
    {
        std::cout << "Animal::eat" << std::endl;
    }
};

class Dog : public Animal {
public:
    virtual ~Dog()
    {
        std::cout << "Dog::~Dog" << std::endl;
    }

    void eat()
    {
        std::cout << "Dog::eat" << std::endl;
    }
};

class Cat : public Animal {
public:
    ~Cat()
    {
        std::cout << "Cat::~Cat" << std::endl;
    }
};
```

==**输出：**==

```
---------- delete animal ----------
Animal::~Animal
---------- delete dog_animal ----------
Animal::~Animal
---------- delete dog ----------
Dog::~Dog
Animal::~Animal
---------- delete cat ----------
Cat::~Cat
Animal::~Animal
```

==**虚函数表**：==

<img src="vtbl_nonV~_animal_dogAnimal.png" width="49%" /> <img src="vtbl_dog_nonV~_cat.png" width="49%" />

图中可以看到，`Animal`、`Dog`、`Cat` 三个表的 `[0]` 槽位都只剩 `eat` 了。`Cat` 写的是普通析构，`vtbl` 表里没有它；但 `Dog` 写的是 `virtual ~Dog()`，它**在表里占着 `[1]`、`[2]` 两个槽位**，只是 `GDB` 没显示出来。

`dog_animal`、`dog` 和 `cat` 的静态类型分别是 `Animal*`、`Dog*` 和 `Cat*`，析构函数不是虚函数，编译器就按静态类型做**静态绑定**：`delete dog_animal` 调 `Animal::~Animal`，`delete dog` 调 `Dog::~Dog`，`delete cat` 调 `Cat::~Cat`。C++ 规定，派生类析构函数执行完毕后，会自动调用基类的析构函数，所以 `delete dog` 和 `delete cat` 会调用 `Animal::~Animal`。

**用一个指向派生类对象的基类指针去 `delete`，而基类析构函数不是虚函数，这是未定义行为（UB）**。`Dog` 自己的析构逻辑被完全跳过、造成资源泄漏，所以基类析构函数必须声明为虚。

用基类指针/引用管理子类对象时，必须保证父类的析构函数是虚的：这样 `delete` 时才会去查 `vtbl`，进而调用到子类的析构函数。查 `vtbl` 用的是**编译期固定下来的字节偏移**：子类沿用父类的 `vtbl` 布局，重写或没重写的父类虚函数在子类 `vtbl` 中的偏移和父类完全一样，所以不管是父类指针/引用指向子类实例、还是本类型指向自己实例，用同一个偏移都能取到正确的函数地址。 

所以**基类必须把所有需要多态调用的函数（包括析构函数）都声明为 `virtual`**。

### 构造函数和析构函数中调用虚函数不会表现多态

原因：`vfptr` 是随构造/析构的进度变化的——构造时先指向基类的表，基类构造完、进入子类构造体之前才改成子类的表；析构时反过来。所以这两个阶段调用虚函数，调到的是**"当前正在构造/析构的那个类"**的版本。

也就是说，不多态的只有**基类**那两段（基类构造时 `vfptr` 还指向基类的表，基类析构时 `vfptr` 已经改回基类的表）；**子类自己**的构造/析构体里 `vfptr` 已经是子类的表，调到的是子类版本——输出里那两行 `Dog::eat` 就是这两处，只是它也不会分派到更下游的类。

```C++
class Animal {
public:
    Animal()
    {
        std::cout << "Animal::Animal()" << std::endl;
        eat();
    }
    
     virtual ~Animal()
    {
        std::cout << "Animal::~Animal" << std::endl;
        eat();
    }

    virtual void eat()
    {
        std::cout << "Animal::eat" << std::endl;
    }
};

class Dog : public Animal {
public:
    Dog()
    {
        std::cout << "Dog::Dog()" << std::endl;
        eat();
    }

    virtual ~Dog()
    {
        std::cout << "Dog::~Dog" << std::endl;
        eat();
    }

    void eat() override
    {
        std::cout << "Dog::eat" << std::endl;
    }
};

int main()
{
    Animal* dog_animal = new Dog();
    dog_animal->eat();
    
    std::cout << "---------- delete dog_animal ----------" << std::endl;
    delete dog_animal;
}
```

**输出：**

<img src="output_cons_des_vfunc.png" style="zoom:70%;" />

- dog_animal初始化时先调用基类构造函数，基类构造中调用虚函数 `eat` 时输出 `Animal::eat` 没有出现多态，因为基类构造期间子类还没构造，`vfptr` 还指向 `Animal` 的 `vtbl`。
- 释放 `dog_animal` 时：析构函数是虚的，先通过 `vtbl` 调到 `Dog::~Dog()`，此时 `vfptr` 还是 `Dog` 的表，析构里调 `eat()` 输出 `Dog::eat`；子类析构体执行完后 `vfptr` 才改回 `Animal` 的表，接着调 `Animal::~Animal()`，里面的 `eat()` 输出 `Animal::eat`（这一步不多态）。

### 纯虚函数

```C++
class Animal {
public:
    virtual ~Animal() = 0;
    virtual void eat() = 0;
};
inline Animal::~Animal() // 纯虚析构函数必须要有实现
{
    std::cout << "Animal::~Animal" << std::endl;
}
inline void Animal::eat()
{
    std::cout << "Animal::eat" << std::endl;
}

class Dog : public Animal {
public:
    Dog()
    {
        std::cout << "Dog::Dog()" << std::endl;
    }

    ~Dog() override
    {
        std::cout << "Dog::~Dog" << std::endl;
    }

    void eat() override
    {
        std::cout << "Dog::eat" << std::endl;
    }

    virtual void get_country()
    {
        std::cout << "Dog::GetCountry" << std::endl;
    }
};
class Cat : public Animal{
public:
     ~Cat() override{ std::cout << "Cat::~Cat" << std::endl;}
};
```

```c++
int main()
{
    Animal* dog_animal = new Dog();
    dog_animal->eat(); // 多态
    dog_animal->Animal::eat(); // 显示调用基类虚函数，前提是基类该函数必须要有定义，否则链接失败

    Dog* dog = new Dog();
    dog->eat();
    // Cat* cat = new Cat(); // Cat没有实现基类全部纯虚函数，还是抽象类，不能实例化。

    std::cout << "---------- delete dog_animal ----------" << std::endl;
    delete dog_animal;
    std::cout << "---------- delete dog_animal ----------" << std::endl;
    delete dog;
}
```

**输出和 `vtbl`：**

<img src="output_purefunc.png" />

<img src="vtbl_purefunc.png" />

- **纯虚析构函数必须要有定义**，没有定义**编译能过、链接会失败**，因为派生类析构执行完会调用基类析构。

- 含纯虚函数的类是**抽象类**，不能实例化；派生类没有实现**全部**纯虚函数时，它自己也是抽象类。

- 纯虚函数**可以有定义**（只能写在类外或者 `.cpp` 中），但是派生类依然必须重写它；想调用那份定义需要显式写类名，`dog_animal->Animal::eat()`。

- 抽象类可以有构造函数、数据成员、普通成员函数，C++ 里的接口可以用全是纯虚函数的抽象类来设计。

  

**在构造函数/析构函数里调用纯虚函数**

```C++
class Animal {
public:
    Animal()
    {
        std::cout << "Animal::Animal()" << std::endl;
        eat();// 构造里调用纯虚函数 → UB
    }

    virtual ~Animal() = default;
    virtual void eat() = 0;
};
inline void Animal::eat()
{
    std::cout << "Animal::eat" << std::endl;
}

// Dog 同上（沿用上面那段代码里的 Dog 定义）
int main()
{
    Animal* dog_animal = new Dog();
    dog_animal->eat();
}
```

- 纯虚函数**没有定义**时：GCC 在构造里已经知道"当前就是 `Animal`"，直接发出对 `Animal::eat()` 的调用 → **链接失败**（`undefined reference to 'Animal::eat()'`）。
- 纯虚函数有定义时：能成功运行且会输出 `Animal::eat` ，在构建时有警告`warning: pure virtual 'virtual void Animal::eat()' called from constructor`

总之是 UB：构造/析构期间虚调用只能落到当前类的版本上，而纯虚函数不保证有定义，即使写了定义、程序恰好能跑（上面第二条），标准也按 UB 处理。所以**不要在构造函数/析构函数里调用虚函数**。
