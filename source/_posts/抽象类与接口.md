# 抽象类与接口

## 抽象类（abstract）

1. **不能实例化**；只能继承。
2. 类的继承是**单继承**：一个类只能继承一个类——不管基类是不是抽象类。抽象类本身可以再继承别的类（包括另一个抽象类），也可以实现接口。
3. 成员几乎和普通类一样全：字段、常量、构造函数、属性、事件……普通类有的它都有。
   - **抽象成员**：`abstract` 修饰，**没有方法体**，具体子类必须实现。只能声明在抽象类里（在非抽象类中声明会报错）；方法、属性、事件、索引器都可以是抽象成员，**字段不行**（C# 没有"抽象字段"）。
   - **虚成员**：`virtual` 修饰，**必须有方法体**（没有方法体又不是 `abstract` 会编译报错），子类可以选 `override` 重写；非抽象类也能定义虚成员。
   - 普通（非虚）方法：可以定义，子类继承，不能重写（可用 `new` 隐藏，不推荐）。
4. **可以没有抽象成员**：全是具体实现也没关系，只要声明了 `abstract` 就不能实例化。
5. **可以部分实现接口**：实现接口时可以不实现全部成员，把剩余的声明成 `abstract`，交给更下层的类完成。
6. **部分实现的继承行为**：抽象类里**已实现**的成员和普通类的成员继承完全一样——下层自动继承、直接可用（下文例子中展示）；接口契约也随继承传递，下层声明里不用再写 `: IShape`，继承链上补完的实现即算满足接口。想让下层**换实现**，该成员必须写成 `virtual`（下层可选 `override`）或 `abstract`（下层必须实现）；写成非虚的普通方法，下层只能继承、不能改。注意：抽象类实现接口成员时可以使用 `virtual`，但是不能使用 `override`——这里没有在重写任何基类成员，两者也不能同时写。
7. 有构造函数：实例构造函数（由派生类 `:base(...)` 链式调用）+ 静态构造函数。
8. 限制：不能 `sealed`、不能 `static`；抽象成员不能是 `private`。

## 接口（interface）

1. 一个类/结构体可以**同时实现多个接口**。一个接口可以继承多个接口。
2. **没有实例状态**：不能声明实例字段（编译报错）；因此接口类型的变量默认值无任何数据。可以声明：
   - **常量**（隐式 `static`，只能是编译期常量）；
   - **C# 8+**：静态字段（不必是编译期常量）、静态构造函数、私有/静态成员。
3. 成员原本只是**签名**：方法、属性、事件、索引器，没有实现（声明即默认 `public`，实现类中相应成员也必须是 `public`）。
4. **C# 8+ 默认接口实现（DIM）**：接口成员可以带方法体，已存在的实现类无需改动即可获得新成员。
   - 注意：默认实现里**没有实例状态可用**（没有字段），只能写计算逻辑、调其他成员。
   - 默认实现的意义是**接口平滑演进**（老实现类不被破坏），不是替代抽象类。
5. **C# 11+ 静态抽象成员**：`static abstract` 成员，用于泛型约束，如 `where T : IAdditionOperators<T, T, T>`，支撑泛型数学（`INumber<T>` 等）。
6. `struct` / `record struct` 可以实现接口——值类型不能继承类，**接口是值类型获得多态的唯一途径**。
7. 泛型约束里接口常用作上限：`where T : ISomeInterface`，且不限制 T 是类还是结构体。

## 语法与功能对比

|                 | 抽象类                                          | 接口                                                         |
| --------------- | ----------------------------------------------- | ------------------------------------------------------------ |
| 实例化          | 不能                                            | 不能                                                         |
| 继承数量        | 只能继承**一个类**                              | 可同时实现**多个接口**（结构体也行）                         |
| 实例字段 / 状态 | 可以（任意类型）                                | 不可以；常量可以（编译期常量），C#8+ 静态字段可以            |
| 构造函数        | 有（实例 + 静态）                               | 无实例构造函数；C#8+ 可有静态构造函数                        |
| 带实现的方法    | 可以（普通 / `virtual`）                        | C#8+ 默认实现可以                                            |
| 无方法体的声明  | `abstract` 成员（子类必须实现）                 | 老版本里所有成员都只是签名                                   |
| 访问修饰符      | 成员自由（`public/protected/internal/private`） | 默认 `public`；C#8+ 可声明 `private` 等                      |
| 成员种类        | 与普通类相同                                    | 方法、属性、事件、索引器、常量；C#8+ 加静态成员              |
| 多态引用规则    | 基类类型引用只能调基类成员                      | 接口类型引用只能调接口成员（这是**所有引用类型的共性**，不是接口特有） |

## 设计上的区别

**接口表达"能做什么"（行为契约，can-do），抽象类表达"是什么和一族共享怎么做"（身份，is-a）。**

### 语义差异

- **接口是给"没有关系的类型"订的合同**：实现同一接口的类之间可以毫无继承关系（字符串、数字、日期都实现 `IComparable`）。调用方只认识接口，不认识任何实现类——低耦合、可替换、易 mock、对依赖注入和单测友好。
- **抽象类是给"有本质亲缘的一族"搭的底座**：`FileStream`、`MemoryStream` 都是 `Stream` 的子类，共享缓冲、读写骨架。抽象类可以携带**共享状态**并保证整族行为一致；接口只约束签名、约束不了语义——两个实现类可以给同名方法完全不同的含义。

### 实际设计时的判断

1. **需要共享状态或实现吗？** 要（字段、构造初始化、`protected` 辅助方法）→ 抽象类；纯粹是行为承诺 → 接口。
2. **实现者是什么关系？** "本质上是同一族" → 抽象类；"碰巧都能干这件事" → 接口。口诀：**"是……"用抽象类，"能……"用接口**（`Bird` 抽象类 vs `IFly` 接口）。
3. **继承额度**：C# 一个类只能继承一个类。用抽象类就花掉了唯一名额并强制树形层级；接口不占名额，可以按能力任意组合（`class Duck : Bird, ISwim, IFly`）。
4. **模板方法模式**——抽象类的用途：基类把算法骨架写成具体方法，关键步骤留给 `abstract` 钩子或 `virtual` 钩子，子类只填钩子：

```csharp
abstract class DataExporter
{
    public void Export()// 骨架：流程定死
    {
        var data = Load();// 钩子1：子类必须提供
        Write(data);// 钩子2：子类可选覆盖
    }
    protected abstract string Load();
    protected virtual void Write(string s) => Console.WriteLine(s);
}
```

5. **经典组合：接口定契约 + 抽象类给骨架**。外部只依赖接口，族内共享实现：

```csharp
interface IShape { double Area(); double Perimeter();}// 契约：谁都能实现

abstract class ShapeBase : IShape// 骨架：一族共用
{
    public abstract double Area();// 接口成员转成抽象，留给子类
    public virtual double Perimeter() => 0; // 默认实现：子类不重写就返回 0
    public string Describe() => $"area={Area()}"; // 共享的默认行为
}

class Circle : ShapeBase
{
    private readonly double _r;
    public Circle(double r) { _r = r; }// 抽象类能存状态，接口不能
    public override double Area() => Math.PI * _r * _r;// 再下层的类不能重写
    public override double Perimeter() => Math.PI * 2 * _r;// 再下层的类可以重写，使用 sealed override之后不能在重写。
}
```

6. **注意**：C# 8 给接口加默认实现后，接口**不能替代抽象类**——默认实现拿不到实例状态、无法做构造初始化，只是给老接口补成员不破坏既有实现者。

## 接口进阶：静态成员、显式实现、签名冲突

> 本节代码与结论均为 **.NET 10 实测**。

### 1. 接口的静态成员与静态构造方法

接口不能有实例字段，**静态成员是接口存放"类型级状态"的唯一途径**（供默认实现等方法共享数据），规则与类的静态成员一致：一份、只能通过**接口名**访问、不随实现类继承。

```csharp
interface ICounter
{
    static int Hits = 0; // 静态字段
    static ICounter() { } // 静态构造函数
    static int Hit() => ++Hits;// 静态方法
}
class CounterImpl : ICounter { }
```

- 访问静态字段：`ICounter.Hit()`；不能用实现类名访问。
- **触发时机**：实例化实现类**不会**触发接口静态构造；**首次访问接口静态成员时**才执行（静态字段初始化 → 静态构造体，仅一次）。
- **C# 11 静态抽象成员（`static abstract`）**：实现类**必须**提供对应的静态实现，但**只能通过泛型约束调用**：

```csharp
interface IFactory<T> where T : IFactory<T>
{
    static abstract T Create();
}
class Product : IFactory<Product>
{
    public static Product Create() => new Product(); // 必须实现
}
static T Make<T>() where T : IFactory<T> => T.Create(); // 泛型内调用
```

用途：泛型工厂模式、泛型数学（`INumber<T>` 等）——实现"静态多态"。

### 2. 显式实现接口成员

```csharp
class Hidden : IHidden
{
    void IHidden.Secret() => ...; // 显式实现：成员名前带 "接口名."
    public void Open() => ...; // 隐式实现：普通 public
}
```

- **不能加任何访问修饰符**——隐式 private，不出现在类的公开表面。
- **类实例访问不到**，必须强转成接口类型：`((IHidden)h).Secret()`。
- 不能是 `virtual`/`abstract`，派生类无法 `override`；想改行为需把接口重新列在派生类声明里"重新实现"。
- 用途：把"履行合同"的成员藏起来、不污染类公开 API（如显式实现 `IDisposable.Dispose`），并用于下面的冲突处理。

### 3. 多接口签名冲突的四种处理

|                         冲突情况                         | 处理                                                         |
| :------------------------------------------------------: | :----------------------------------------------------------- |
|            同名同签名（`IA.M()` + `IB.M()`）             | 实现**一个** `public M()` 同时满足两个接口，经任一接口引用调用都到它 |
|           同名同签名，但两个接口行为要**不同**           | 写两个显式实现 `void IA.M()` + `void IB.M()`，各管各的       |
|     同名**不同参数**（`Same(int)` + `Same(string)`）     | 不算冲突，实现成两个重载，各自隐式满足对应接口               |
| 同名、仅**返回类型不同**（`int Get()` + `string Get()`） | 一个方法无法同时满足，至少一个必须**显式实现**               |

要点：签名冲突不会造成"调用歧义"——调用点变量的接口类型已消歧；冲突只发生在"用一个类成员同时实现两个接口成员"的层面。**隐式实现 = 两接口共享同一行为（耦合）；显式实现 = 各自独立**。
